## 1. מבוא

במסגרת המיני פרויקט נבחרה מערכת לניהול שדה תעופה, ומתוכה יחידת **ניהול החנויות והמסחר**. היחידה עוסקת בניהול החנויות הפועלות בשדה התעופה, המוצרים שהן מציעות, מלאי המוצרים, מחירי המכירה ותיעוד העסקאות המתבצעות בחנויות.

מטרת המערכת היא לרכז מידע מסחרי במסד נתונים יחסִי, לאפשר מעקב אחר חנויות ומוצרים, לנהל מלאי ומחירים לכל חנות בנפרד, לתעד מכירות ללקוחות ולשמור את פרטי המוצרים והמחירים בכל עסקה. המבנה מאפשר לבצע שאילתות על פעילות החנויות, על מלאי ועל היסטוריית המכירות.

המערכת ממומשת באמצעות **PostgreSQL 19**, וניהול מסד הנתונים ובדיקת השאילתות נעשים באמצעות **pgAdmin 4**.

## 2. היכרות עם המערכת והיחידה הנבחרת

המערכת כוללת שבע טבלאות:

| טבלה | תפקיד |
|---|---|
| `Stores` | פרטי החנויות: שם, סוג, טרמינל, שער, תאריך פתיחה וסטטוס פעילות. |
| `ProductCategories` | קטגוריות המוצרים, כולל שם ותיאור אופציונלי. |
| `Products` | פרטי המוצרים, לרבות שם, ברקוד, עלות ליחידה וסטטוס פעילות. |
| `StoreProducts` | שיוך מוצרים לחנויות, מחיר מכירה, כמות במלאי, סף לחידוש מלאי ותאריך מילוי אחרון. |
| `Customers` | פרטי לקוחות: מספר מזהה, שם פרטי, שם משפחה, סוג לקוח וכתובת דוא״ל. |
| `Sales` | נתוני עסקאות: מועד, אמצעי תשלום, סטטוס, לקוח, חנות והפניה לטיסה. |
| `SaleItems` | שורות המכירה: מוצר בחנות, כמות ומחיר ליחידה בעת המכירה. |

**פעולות מרכזיות שהמערכת מיועדת לתמוך בהן:** צפייה בחנויות ובמוצרים, בדיקת מלאי ומחירים לפי חנות, תיעוד עסקאות, הצגת פריטי מכירה ושליפת מידע באמצעות שאילתות SQL.

## 4. תרשים ERD

תרשים ה־ERD מתאר את הישויות, המאפיינים והקשרים ביניהן.

![תרשים ERD של מערכת ניהול החנויות והמסחר](ERD.png)

### הקשרים המרכזיים

- **חנויות ומוצרים (`Offers`):** קשר רבים־לרבים הממומש באמצעות `StoreProducts`, כך שמוצר יכול להימכר בכמה חנויות וחנות יכולה להציע מוצרים רבים.
- **מוצרים וקטגוריות (`Categorizes`):** כל מוצר משויך לקטגוריה, וקטגוריה יכולה להכיל מוצרים רבים.
- **לקוחות ומכירות (`Purchases`):** לקוח יכול להיות משויך למספר עסקאות.
- **חנויות ומכירות:** כל מכירה משויכת לחנות שבה התבצעה.
- **מכירות ופריטי מכירה (`Contains`):** מכירה יכולה לכלול מספר שורות פירוט.
- **פריטי מכירה ומוצר בחנות (`RefersTo`):** כל שורת מכירה מתייחסת לרשומת מוצר בחנות (`StoreProducts`).

## 5. תרשים DSD – סכימה יחסית

תרשים ה־DSD מציג את הטבלאות, השדות, המפתחות הראשיים והמפתחות הזרים במימוש היחסי.

![תרשים DSD של מערכת ניהול החנויות והמסחר](DSD.png)

הסכימה כוללת את `Stores`, `ProductCategories`, `Products`, `StoreProducts`, `Customers`, `Sales` ו־`SaleItems`.

מפתחות זרים מקשרים בין המוצרים לקטגוריות, בין המלאי לחנויות ולמוצרים, בין המכירות לחנויות וללקוחות, ובין שורות המכירה למכירות ולרשומות המוצרים בחנויות. בקובץ הגיבוי אומתו גם אילוצי ייחודיות, ובהם ברקוד מוצר וקשרים ייחודיים בין חנות למוצר ובין מכירה לחנות בהתאם למימוש.

**בדיקה לפני הגשה:** יש לוודא שהתרשימים `ERD.png` ו־`DSD.png` נמצאים לצד קובץ ה־README, ושהשדות, סוגי הנתונים והאילוצים בתרשים תואמים לקובץ יצירת הטבלאות הסופי.

## 6. החלטות תכנון

1. **הפרדה בין מוצרים לחנויות:** `Products` שומרת את פרטי המוצר הכלליים, ו־`StoreProducts` שומרת מחיר ומלאי שונים לכל חנות.
2. **טבלת קטגוריות נפרדת:** `ProductCategories` מונעת חזרה מיותרת על פרטי קטגוריה ומאפשרת שיוך מוצרים בצורה עקבית.
3. **הפרדת מכירה משורותיה:** `Sales` מכילה את פרטי העסקה, ו־`SaleItems` את המוצרים והכמויות בכל עסקה.
4. **שמירת מחיר היסטורי:** `UnitPriceAtSale` בטבלת `SaleItems` מתעד את המחיר בעת המכירה, גם אם מחיר המוצר ישתנה בעתיד.
5. **שמירה על שלמות קשרים:** הוגדרו מפתחות ראשיים, מפתחות זרים ואילוצי ייחודיות כדי לצמצם כפילויות והפניות לרשומות שאינן קיימות.
6. **הפניות למערכת הרחבה:** השדות `Flight_ID_FK` ו־`Gate_Id_FK` מיועדים לקישור לישויות חיצוניות של מערכת שדה התעופה. בשלב זה לא הוגדרו עבורם אילוצי מפתח זר לטבלאות שאינן חלק מהיחידה הנבחרת.

## 8. גיבוי ושחזור

### 8.1 גיבוי בפורמט Custom

בוצע גיבוי של `AirportCommercialDB` לקובץ `AirportCommercialDB.backup` באמצעות `pg_dump` של PostgreSQL 19, דרך Command Prompt ב־Windows:

```bat
"C:\Program Files\PostgreSQL\19\bin\pg_dump.exe" -h localhost -p 5432 -U postgres -F c -f "%USERPROFILE%\Downloads\AirportCommercialDB.backup" AirportCommercialDB
```

תקינות מבנה קובץ הגיבוי נבדקה באמצעות:

```bat
"C:\Program Files\PostgreSQL\19\bin\pg_restore.exe" -l "%USERPROFILE%\Downloads\AirportCommercialDB.backup"
```

הפקודה הציגה את שבע הטבלאות, מקטעי הנתונים והאילוצים שבארכיון. בדיקה זו מאמתת שניתן לקרוא את תוכן הארכיון, אך אינה מחליפה בדיקת שחזור מלאה.

### 8.2 גיבוי בפורמט SQL

נוצר גם גיבוי טקסטואלי בפורמט Plain SQL, המכיל פקודות ליצירת מבנה מסד הנתונים ולהכנסת הנתונים:

```bat
"C:\Program Files\PostgreSQL\19\bin\pg_dump.exe" -h localhost -p 5432 -U postgres -F p --no-owner --no-privileges -f "%USERPROFILE%\Downloads\AirportCommercialDB.sql" AirportCommercialDB
```

הקובץ `AirportCommercialDB.sql` נפתח ונבדק כקובץ טקסט, ובו הופיעו הוראות `CREATE TABLE` ו־`COPY` לנתוני הטבלאות.

### 8.3 התאמת גרסאות הכלים

במהלך העבודה נמצא ש־pgAdmin השתמש בכלי `pg_dump` או `pg_restore` בגרסה 18.6 מול שרת PostgreSQL 19.0, דבר שגרם לשגיאת אי־התאמת גרסאות. לכן נעשה שימוש ישיר בכלי הגיבוי והשחזור המותקנים בנתיב `C:\Program Files\PostgreSQL\19\bin`.

### 8.4 שחזור במחשב נוסף

קובץ הגיבוי מיועד לשחזור במסד נתונים ריק במחשב נוסף שבו מותקן PostgreSQL 19. ניתן לבצע את השחזור באמצעות `pg_restore` מגרסה 19:

```bat
"C:\Program Files\PostgreSQL\19\bin\pg_restore.exe" -h localhost -p 5432 -U postgres -d AirportCommercialDB --no-owner --no-privileges "%USERPROFILE%\Downloads\AirportCommercialDB.backup"
```

**סטטוס:** [להשלים לאחר ביצוע שחזור מוצלח במחשב השני ואימות ספירות הרשומות]. אין להריץ את השחזור לתוך מסד נתונים המכיל כבר טבלאות ונתונים בלי לבדוק את השפעת הפעולה.
